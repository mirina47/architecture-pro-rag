# Исследование моделей и инфраструктуры

Сравнение по уровням: высокий, средний, низкий.

## 1. Сравнение LLM-моделей
| Критерий                           | Локальные Hugging Face                                                                                               | Облачные OpenAI / YandexGPT                                                 |
|------------------------------------|----------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| Качество ответов                   | Средний (зависит от выбранной модели и ее размера)                                                                   | Высокий (используются крупные модели, обученные на огромных наборах данных) |
| Скорость работы                    | Средний (зависит от мощности локального сервера и наличия GPU)                                                       | Высокий (обработка выполняется на мощной облачной инфраструктуре)           |
| Стоимость владения и использования | Средний (разовые затраты на сервер и последующие расходы на поддержку инфраструктуры)                                | Средний (оплата за использование API и количество токенов)          |
| Удобство и простота развёртывания  | Низкий (необходимо самостоятельно разворачивать модель, настраивать окружение и инфраструктуру)                      | Высокий (требуется использовать готовый API сервиса)                       |

**Вывод:** Облачные OpenAI / YandexGPT обеспечивают более высокое качество ответов и значительно проще в интеграции. Локальные Hugging Face дают больший контроль над данными, но требуют дополнительных ресурсов для настройки и поддержки.

## 2. Сравнение моделей эмбеддингов
| Критерий                           | Локальные Sentence-Transformers                                                           | Облачные OpenAI Embeddings                                                 |
|------------------------------------|-------------------------------------------------------------------------------------------|----------------------------------------------------------------------------|
| Скорость создания индекса          | Средний (создание эмбеддингов выполняется на локальном сервере и зависит от его мощности) | Высокий (эмбеддинги создаются на оптимизированной облачной инфраструктуре) |
| Качество поиска                    | Средний (качество зависит от конкретной модели)                                           | Высокий (модели обучены на больших датасетах)                              |
| Стоимость владения и использования | Низкий (после развертывания нет дополнительных расходов за использование)                 | Средний (стоимость зависит от количества запросов к API)                   |

**Вывод:** Облачные OpenAI Embeddings обеспечивают более точный семантический поиск, но приводят к регулярным расходам. Локальные Sentence-Transformers позволяют снизить стоимость эксплуатации и хранить данные внутри инфраструктуры компании.

## 3. Сравнение векторных баз
| Критерий                                 | ChromaDB                                                                                            | FAISS                                                                              |
|------------------------------------------|-----------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------|
| Скорость поиска и индексации             | Средний (использует дополнительные уровни абстракции, что может немного снижать производительность) | Высокий (оптимизированная библиотека для быстрого поиска ближайших векторов)       |
| Сложность внедрения и поддержки          | Средний (имеет собственный сервер и дополнительные компоненты)                                      | Низкий (библиотека подключается напрямую в приложение)                             |
| Удобство в работе                        | Высокий (предоставляет готовый интерфейс для хранения, обновления и управления коллекциями)         | Средний (предоставляет только механизм поиска, без полноценной системы управления) |
| Стоимость владения (учёт инфраструктуры) | Низкий (можно запускать локально без дополнительных сервисов)                                       | Низкий (работает как библиотека внутри приложения)                                 |

**Вывод:** FAISS обеспечивает высокую производительность и простоту внедрения. ChromaDB предоставляет больше возможностей для управления данными, но может быть немного сложнее и медленнее.

## 4. Рекомендуемая конфигурация сервера
- CPU: 8-16 vCPU (для обработки большего количества запросов)
- RAM: 32-64 GB (для хранения более крупных индексов)
- GPU: NVIDIA T4 / A10 (если используется локальная LLM)
- SSD: 300+ GB (для хранения документации)

## 5. Вывод
Наиболее подходящей является **гибридная архитектура**:
- LLM: Облачные OpenAI / YandexGPT  
- Embeddings: Локальные Sentence-Transformers  
- Векторная база: FAISS  

Такое решение позволяет:
- использовать более мощные облачные модели для генерации качественных ответов;
- хранить данные внутри инфраструктуры компании;
- снизить стоимость эксплуатации;
- обеспечить высокую скорость поиска благодаря FAISS.
